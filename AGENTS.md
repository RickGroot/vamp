# Vamp — AGENTS.md

100% local-first, offline, installable PWA for sketching chord progressions and looping backing tracks to improvise over, plus a Practice workspace of generated drills (scale patterns and chord tones, through every key, in your own written range). SvelteKit + Svelte 5 (RUNES) + TypeScript + SCSS. Music theory via **tonal**, audio clock/AudioContext via **tone**, sampled instruments + TR-808 via **smplr**, notation via **vexflow**, persistence via **idb** (IndexedDB). No backend, no network except the sample CDN (runtime-cached). Deployed as a static SPA to GitHub Pages under base path `/vamp/`.

## Commands

- `pnpm dev` — vite dev (served at ROOT, not `/vamp/`).
- `pnpm build` — vite build (static, base `/vamp`). `pnpm preview` — serve the build.
- `pnpm check` — `svelte-kit sync && svelte-check` (typecheck; **there is no lint script**).
- `pnpm test` — `vitest run` (all suites). `pnpm test:watch` — vitest watch.
- `node scripts/gen-assets.mjs` — the icon set (+ `--share` for og-image, `--screenshots <app url>` for the install screenshots; those two drive a local headless Chrome, no npm dependency). Re-run after any change to the mark or the look.
- Single test: `pnpm test <path>` (e.g. `pnpm test src/lib/audio/comp.test.ts`) or `pnpm exec vitest run -t "<name>"`.
- pnpm@11.1.2; installs use `--ignore-scripts` + `minimumReleaseAge` (org policy). Always run `pnpm check` + `pnpm test` before committing.

## Deploy / CI / base path

- `.github/workflows/deploy.yml`: on push to `main` → `pnpm install --frozen-lockfile --ignore-scripts` → **`pnpm check` → `pnpm test`** → `pnpm build` → `cp build/200.html build/404.html` → deploy to Pages (node 22). Live: https://rickgroot.github.io/vamp/. The checks gate the deploy — a push to `main` publishes straight to the live site, so a failure must stop it here.
- **base path `/vamp` applies to BUILD ONLY; dev stays at root.** Never hardcode `/vamp/` in code — use SvelteKit's `base` from `$app/paths`. `src/app.html` hardcodes the GH-Pages origin only in `og:url` / `og:image` / `twitter:image`; icons/manifest use `%sveltekit.assets%`.
- No `svelte.config.js` — SvelteKit config is INLINE on the `sveltekit()` plugin in `vite.config.ts` (adapter-static, SPA fallback `200.html`, runes forced on for app code). `ssr=false` + `prerender=true` live in `src/routes/+layout.ts` (CSR/SPA; there is no `+page.ts`).
- **`paths.relative: false` is load-bearing now that there is a sub-route.** Relative asset URLs resolve against the *document*, so `/vamp/practice/` (trailing slash) looked for `/vamp/practice/_app/…` and 404'd the whole app. Absolute `/vamp/_app/…` is immune. Don't flip it back.
- `scripts/preview-static.mjs` (port 5181) mirrors GH Pages' real lookup order — `practice.html`, then `practice/index.html`, then the `404.html` shell. Use it, not `pnpm preview`, to verify deep links and offline behaviour under `/vamp/`.
- `buildShareUrl` pins the link to the SKETCH path via `base`, never `location.pathname` — sharing from `/practice` would otherwise mint a link that opens Practice, where nothing reads the hash. `readSharedProgression()` runs in `+layout.svelte`, so a shared link works whichever route it lands on. It is loaded with `{ adopt: progression.isBlank }` — shown, but not made the draft, unless the canvas was empty (see the draft convention) — and the hash is then CONSUMED with `replaceState`. Left in the address bar, every reload re-applied the pristine shared song and the next edit saved it over the user's work. That `replaceState` is deferred one macrotask: SvelteKit's router isn't started during `onMount`, and in dev its `replaceState` throws until it is.
- **The SW `navigateFallback` answers EVERY navigation with the app shell** unless denylisted — `navigateFallbackDenylist: [/\.txt$/, /\.xml$/]` keeps the non-precached `robots.txt` / `llms.txt` / `sitemap.xml` reachable inside an installed PWA. A new file of that kind needs to match the pattern (or be precached).
- **SEO lives entirely in `src/app.html`, and is per-SITE not per-ROUTE.** `ssr=false` means a prerendered route is only the shell, so `<svelte:head>` never reaches a scraper — `/vamp/practice` shares the root's title, description and `og:url`. `<svelte:head><title>` still updates the tab for humans. Changing that needs SSR, which this app deliberately doesn't have. `static/sitemap.xml` is hand-maintained: add a line when a route is added.

**Two routes: `/` (Sketch — the chord editor) and `/practice` (generated drills).** Shared chrome — frame, header, Sketch/Practice nav, pitch select, the Light/Auto/Dark theme switch, the field (`--field`/`--on-field`: the one block of colour, set from the sounding chord or the tune's colour), the screen wake lock, the one notice toast, keyboard shortcuts, the share-hash read and the drone key-sync — lives in `+layout.svelte`; each route owns only its own `<main>`.

## Key data flow

**Playback:** Progression → `schedule.buildScheduledEvents` (flattenSlots → voiceSequence + parseChord → CompSlot[] with bassMidi/bassPcs) → `comp.buildCompEvents` (CompEvent[] positioned in quarter notes) → `engine.buildEvents` (quarters × PPQ → tick strings `"Ni"`) → looped `Tone.Part` on the Transport. Chords = smplr instrument; bass = its own `groove.bassInstrument` voice (upright/electric/synth), or the chord instrument when `bassInstrument==='keys'`; drums = smplr TR-808; metronome = tiny Tone.Synth. All share ONE AudioContext (`context.getRawContext`). Active-slot highlight dispatched via `Tone.getDraw()` at audio time.

**Chords are stored as the LITERAL symbol string the user typed** and re-parsed with tonal at play/render time — never cache a parsed form. Empty string = rest. Durations are in beats (beat unit = TS denominator).

**Export:** `buildScheduledEvents(progression, {whole:true})` renders the WHOLE progression (default covers only the active loop range); midi.ts/audio.ts serialise, skipping `ev.kind==='click'`.

**Notation spelling:** bars → `displayChord(chord, view.offset)` (WRITTEN pitch) → parseChord → `notationVoicing` (stacks into a fixed B3–G5 window, keeps the symbol's spelling as `{midi,name}`) → `voicedToVexKey` → StaveNote. The `name` decides letter+accidental; MIDI only fixes the octave.

## State & stores

Each `stores/*.svelte.ts` exports ONE eagerly-constructed singleton — no barrel, import directly. Constructors read localStorage only under `browser`; setters write. **Engine sync happens in setters, not in `$effect`s** (view.syncMix/setTradeBars, drone setters, progression.setTempo).

- `progression` = the hub: current song, undo/redo, playback wiring, transient practice-drills. Registers `engine.onActiveSlot/onState/onLoop`; `play()` passes `{countIn: view.countIn, clickFeel: drills.clickFeel}`. Undo history capped at `HISTORY_LIMIT=100`; same-`tag` edits coalesce within `COALESCE_MS=700`. `MAX_SLOTS_PER_BAR=4` (a bar splits full→half→…→4). `setTimeSignature` redistributes each bar's beats to fill the new meter while keeping slot COUNT. The song on the canvas autosaves to `vamp:draft` (`DRAFT_DEBOUNCE_MS=400` after `touch()` / undo / redo / an adopted `load()`, flushed on `pagehide` and on hide) and is restored in the constructor, before first render — so a reload, a closed tab or a relaunched PWA reopens where you left off.
- `view` = per-device prefs + rhythm-section mix/trade pushed live to the engine. `drills` = drill prefs. `droneState` = pedal-tone, wraps the audio `drone` singleton (**the store is `droneState`, the engine is `drone`**). `library` = reactive mirror of IndexedDB (`refresh()` after each mutation; failures land in `library.error`, not thrown). `scales`, `midi`, `recorder` = session-only (scales remembers its root/type/view/open). `view.sections` remembers which Sketch sections are open (`vamp:sections`; first visit: Notation open, Band + Woodshed + Scales closed). The old `vamp:art` key (and `view.artMode`) is gone. `view.themePref` = `'auto' | 'day' | 'night'`, shown as Light / Auto / Dark (`vamp:theme`; `setTheme` writes `data-theme` on `<html>` in the setter; `app.html`'s inline script applies it before first paint — keep the key in step); `view.night` is the resolved theme for anything drawn outside CSS. `progression.recent` = the recent-sketch list (`resumeSketch` / `forgetSketch`). `notice` = the ONE transient toast, session-only: `show(text, action?)` returns an id, a newer notice replaces the old (never a stack), an action notice lasts 6s and holds while hovered or focused. `library.remove()` resolves to the removed record so `library.restore()` can put it back unchanged (same id + `updatedAt`, so the same place in the list) — deletes are undoable, not confirmed.
- `drillLibrary` = reactive mirror of the custom-drill store (`refresh()` after each mutation; failures land in `drillLibrary.error`, not thrown) — the drill-side twin of `library`.
- `practice` = the generated-drill workspace: current definition, run options, the frozen run on the transport, and the cue. A saved custom drill wins over a built-in with the same id. **Its derived values (`definition`, `usesSong`, `songChords`, `songIsEmpty`, `range`, `preview`, `run`) are `$derived` FIELDS, not getters** — a getter recomputes on every read, and these are read from several components and from each other, so each settings change re-resolved the whole drill several times over. `playing` is `$state.raw` so `run` can follow it without deep-proxying every note of a twelve-key run. **Guide-tone drills read `progression.current` live** (through `loopBars`, so "Practise this" honours the loop range) and transpose a COPY per repetition — the editor's song is never mutated, which is the whole reason not to reuse Sketch's key-cycle machinery. Subscribes to `engine.onActiveCue` ONLY; `start()` calls `engine.stop()` first so the progression store can restore any transient song drill. `resolveDrill` runs on every settings change (cheap, pure) so the notation previews what Start will play; the frozen run wins while playing.
- **localStorage** (all `vamp:`-prefixed, defensive reads): view (`vamp:transpose|countIn|roman|mix|trade|sections|theme`), drills, drone, scales, practice (`vamp:practice`), the working song (`vamp:draft`) and recent sketches (`vamp:recent`). **IndexedDB:** the library (saved songs) + custom drills. **Session-only:** recorder, midi, notice, and the undo history (the song is restored on launch; its history is not).

## Conventions (bug-prevention — ignoring these reintroduces a fixed bug)

- **`engine.start()` generation guard.** Every `await` inside `start()` is followed by `if (gen !== this.playGen) return;` and the catch is gen-guarded; stop()/new start() bump `playGen`. BOTH `Tone.getDraw()` highlight callbacks also check `gen === this.playGen` — `_state==='playing'` only covers a *stop*, not a *replacement*, and a stale draw would otherwise leave a slot lit forever. → a stale/superseded play must not bleed over the new song.
- **The engine takes a `PlaybackPlan`, not a Progression.** There is ONE Tone Transport, so there is one engine, shared by the song and by generated drills. `play(progression)` is a thin adapter over `start(plan)`; `progressionPlan()` (schedule.ts) and `drillPlan()` (practice/plan.ts) are the two producers. `plan.source` is REQUIRED so a new producer cannot forget to declare itself.
- **Two highlight channels, provably disjoint.** `slotIndex` is the `flattenSlots` global index the editor keys on (BarCard/StaffSheet); `cueIndex` is a generated plan's own note index. Progression events set only the first, drill events only the second; the progression store never subscribes to `onActiveCue`, the practice store never to `onActiveSlot`. A `comp.test.ts` guard locks it. → a drill setting `slotIndex` lights up a chord in the user's song.
- **Anything reacting to the engine must check `engine.source` first.** The progression store registers `onState`/`onLoop`/`onActiveSlot` in its constructor, permanently — so a drill's loop boundary reaches `onDrillLoop` too. It early-returns unless the source is `'progression'`, and `isPlayingThis` (not `isPlaying`) gates all 16 `void this.play()` restart sites plus undo/redo. → otherwise a drill silently transposes and re-tempos the user's saved song.
- **A drill pre-generates EVERY repetition into one plan.** Never regenerate per loop: that is `transport.stop() + cancel() + position = 0` — an audible seam at every key change — and it re-awaits the instrument caches, so one evicted sample drops you to `'stopped'` mid-session. Tempo step-up still works live, because note duration is derived from the current bpm inside the Part callback.
- **`unlockAudio()` (context.ts) must run synchronously from a real user gesture** before any playback; engine.play / drone.start / playScale all await it. → prevents no-audio on mobile / a suspended context.
- **Custom drills route through `migrateDrill` (drillDb.ts)**, the drill-side twin of `migrateProgression`, with the same reasoning: `pattern.rhythm` entries must be >0 and ≤64 (a zero duration corrupts tick maths and can freeze scheduling), cell offsets and `step` clamp to ±24, `cellsPerKey` to 64, unknown scale types / chord qualities / guide lines / directions fall back. A stored `builtIn: true` is never trusted — an imported file must not pose as part of the shipped library. **`DB_VERSION` is 2**; drills live in the same `vamp` database via the fall-through `upgrade` block, and `getDb()` is exported from db.ts for that.
- **`VampBackup.drills` is OPTIONAL and the song `schemaVersion` stays 1.** Every pre-Practice backup still imports, the key is omitted entirely when there are no drills, and `importProgressions` imports drills FIRST and independently — a malformed `drills` field must not cost the user the songs beside it, and a backup with drills but no saved songs must not throw "no songs found".
- **ALL persistence routes through `migrateProgression` (db.ts)** — db reads, `importProgressions`, `share.decodeProgression`. Add a persisted field → add its `coerce*` default there AND document it in `static/llms.txt` (`storage/llms.test.ts` imports every example in that guide, so a schema change without a doc update fails the suite); never trust a raw record. Its bounds are load-bearing: `slot.beats` >0 and ≤64; TS numerator 1–16, denominator ∈ {2,4,8,16}; tempo clamped 20–300; empty bars → `[createBar()]`, empty bar → one slot. → a hostile share hash with `beats≤0` corrupts MIDI ticks / freezes scheduling. Legacy path: `coerceGroove.bass` maps boolean `true→'root'`, `false→'none'` — any new persisted enum needs the same.
- **The draft is the canvas, not the library** (`storage/draft.ts`, `vamp:draft`). It keeps the song's `id`, so Ctrl+S after a reload still updates the library entry it came from. Every mutation reaches it through `touch()`, so a new mutation needs nothing extra — but a new path that REPLACES `current` must go through `load()`, which decides adopt-or-show, and which pushes the OUTGOING song onto the undo history — so Examples / New / Open / Import / a shared link are one Undo from your sketch, announced by a "Replaced … · Undo" notice when that song had chords (`announce: false` for a same-chords load like Save as a copy). Any other history move (`checkpoint` / undo / redo / load) retires that notice, or its Undo would undo the wrong step. Four rules keep it from eating work: (1) `load(p, { adopt: false })` — a shared link over a non-blank canvas — cancels the pending save and holds saving until the first edit (`touch()` re-arms `draftable`); (2) it is NOT written while a Sketch key-cycle / tempo drill has the song transposed (`drillOrigin` set) — `endDrillSession()` reschedules once the key is restored, or a mid-drill reload would reopen the song in the wrong key; (3) `flushDraft()` writes only when a save is PENDING, so a tab you merely looked at can't overwrite another tab's newer draft on hide, and an HMR-orphaned store instance stays silent; (4) reads route through `migrateProgression`, and a corrupt draft is removed rather than blocking launch. Known limits: multi-tab is last-writer-wins, undo history is not restored, and edits made while a Sketch drill runs are only saved once it stops.
- **Tempo/TS bounds live ONLY in `model/factory.ts`** (re-exported by the progression store; drills imports from factory). UI clamp and db coercion both import from here — change bounds in one place.
- **Keep pure modules pure:** comp / mix / drills / voicing / chord / transpose / tapTempo import no `tone` and no stores. → keeps them node-unit-testable and out of the AudioContext graph.
- **`flattenSlots` (slots.ts) is the single source** of the global slot index the engine and UI key on — don't recompute it elsewhere.
- **Schedule in transport TICKS** (`${round(quarters*PPQ)}i`), never seconds; derive note duration live from current bpm inside the Part callback so tempo changes apply without a restart. `setTempo()` just sets `bpm.value`.
- **Clamp note duration to the slot boundary** (`Math.min(step, quarters - offset)` in comp.ts); `GAP=0.95` / `BASS_GAP=0.92` leave a de-blur gap. → fractional-beat slots otherwise ring past the next attack.
- **A rest/empty slot still emits `kind:'chord'` with `midi:[]`** to drive the highlight — don't drop it. `parseChord` distinguishes `isRest` (blank) from unrecognised (`empty:true, isRest:false`); both yield `midi:[]` but mean different things to the UI.
- **`nearestMidi` (voicing.ts) folds by octaves within 36–88, never hard-clamps** — a clamp changes pitch class (Bb near the floor would sound as C).
- **Structural/schedule-changing mutations restart playback while playing** (`if (this.isPlaying) void this.play()`): setInstrument, setTimeSignature, setPattern, setBassMode, toggleMetronome, setDrums, transpose, inspire, removeBar, moveBar, applyPreset, addSlot, removeSlot, set/clearLoopRange. **Pure appends do NOT:** addBar, inputChord, appendChordBar, setSlotChord. setTempo/setName stay live/silent. Follow this split for any new mutation.
- **`loopRange` is stored by BAR INDEX** (survives reorder); removeBar/moveBar remap it; read via `resolveLoopRange`/`loopBars` (they clamp) — never index bars with the raw range.
- **Every progression mutation calls `checkpoint(tag)` then `touch()`.** Practice-drill changes are TRANSIENT and must never enter undo history; `undo()`/`redo()` call `endDrillSession()` FIRST.
- **Chord-building modules validate every generated symbol with `isValidChordSymbol`** and fall back to the bare note; always `Note.simplify()` after `Note.transpose()` — **for ROOTS and CHORD SYMBOLS only.** For MELODIC note names use `practice/spelling.ts`'s `readable()`, which collapses double accidentals and nothing else: `Note.simplify` rewrites single accidentals too (`'Cb5'→'B4'`, `'E#4'→'F4'`), which destroys the correct spelling of Gb major and F# major. Scales really do emit double accidentals in ordinary keys (Ab blues has an `Ebb`) — 25 of the 168 root×type combinations — and the root is never respelled, so "Eb blues" never becomes "D# blues". `spelling.test.ts` pins Gb major's `Cb` and F# major's `E#` so a revert to a blanket simplify fails loudly.
- **Practice resolves in WRITTEN pitch; the key plan stays CONCERT.** The offset is applied exactly once, to the key root, and playback converts back via `concertMidi`. Range is a written property (a trumpet's low F#3 is written), spelling is a written property, and a `DrillNote`'s `name` and `midi` must agree or `voicedToVexKey`'s letter-based octave solve breaks. A `DrillRun` is transient, like `detections` — only the definition persists, and it is key- and offset-free.
- **Every range adjustment moves MIDI by a WHOLE multiple of 12** (`fitOctave`/`foldIntoRange`). `name` is fixed before fitting and never touched after; any other shift desyncs the pair and the staff silently falls back to flats. One assertion in `range.test.ts` covers that whole failure class. A scale/chord phrase too wide for the range SKIPS that key and says why — never clamp, never truncate.
- **Guide-tone lines FOLD into range as they are built; they are never skipped or re-centred.** Nearest-note voice leading is path-dependent — it need not return to its starting pitch after a pass of the form — so a real tune drifts: a 16-bar form started each chorus lower (65, 60, 48, 36), spanning 46 semitones over 64 changes, and the phrase-level span check rejected it in EVERY key, leaving "Practise this" empty on any real standard. `guideToneLine` takes the range and folds per note. And do NOT run `fitOctave` on the result: a folded line has a misleading average pitch, and re-centring by average shoved "middle" an octave above "high". The seed already places the line in the register.
- **Transposition split:** the store keeps CONCERT pitch. ChordSlot shows `displayChord(chord, view.offset)` and writes `concertFromDisplay(draft, offset)`; while focused it shows the live `draft` (never re-spelled under the cursor). Notation always feeds `displayChord`. ScalesSection follows the same rule: `scales.root` is CONCERT (playback sounds concert), but the whole section DISPLAYS a `displayInfo` rooted on the written root; the root select round-trips via `concertFromDisplay`.
- **Menus (File/Share/Preset/Example/Suggest) are disclosure popovers, NOT `role=menu`:** `use:dismissable` + `onfocusout`, rows are plain `<button>`. Only ChordSlot autocomplete is a real `role=combobox/listbox` (with `aria-activedescendant`).
- **Keyboard shortcuts live ONLY in `+layout.svelte`** (`<svelte:window onkeydown>`), so they work identically on both routes. Space = play/stop (skipped in form fields and when focus is on `closest('button,a,select,input,textarea,[contenteditable]')`); Ctrl/Cmd+S quick-save; Ctrl/Cmd+Z undo, Ctrl/Cmd+Y or Shift+Z redo (skipped in fields to preserve native undo).
- **The top of Sketch is laid out by CONTAINER queries on `.editor` (and `.deck-host`), not viewport media queries**, in deliberate arrangements (desktop / tablet ≤900px for the deck / phone ≤540–560px) — the title on its own line, the toolbar under it (history · File/Share on the left, Stand/Practise on the right), the deck, Add chords (one row), then the chart header (pattern chips + Roman numerals). The deck's panel rules are its grid GAPS showing the ink behind, so they stay exact in every arrangement. A container can't query itself: the deck's container is its `.deck-host` wrapper. Don't reintroduce ragged `flex-wrap` rows or swipe strips there.
- **Add editor UI by composing into `+page.svelte`'s `<main class="editor">`.** A third route needs a real reason — chrome, nav, prerender and the share URL all have to be considered. Section components read/mutate stores directly; props are reserved for derived cross-cutting values (e.g. `keyInfo`). Anything shared by both routes belongs in `+layout.svelte`.
- **The shared header wraps to two rows below 600px** (`+layout.svelte`), and `.head__left`/`.head__right` carry `min-width: 0` — without it a flex child refuses to shrink below its content width and pushes the pitch select off-screen instead of wrapping. Same rule applies to any new toolbar row: `flex-wrap: wrap`, not `flex: 0 0 auto`.
- **Colours: `app.scss` is the single token source — components use `var(--…)`, never raw hex.** `classifyChord` → family → `--c-{family}` (major yellow / minor blue / dominant orange / diminished magenta / augmented green / suspended cyan / other grey — flat printing inks that all take black text ≥5:1 in both themes). **Chord colours mean chord quality and nothing else.** A chord sits under a 6px tab of its ink; the sounding chord is a SOLID block of its ink with `--on-pigment` text. **"On" is inked solid** (`--spot` = ink: on-toggles, the chosen theme segment, primary buttons); the place you are (nav) is underlined, not filled. **The field is the ONE block of colour on a page** — `--field`/`--on-field`, written on `<html>` by the layout: the sounding chord's ink while playing, the tune's most-used family at rest, `--field-rest` when blank / a rest / a drill. It changes as a CUT (no transition), so field and ink can't disagree mid-way. ChordSlot / the stand / the dock set inline `--q`. Focus is a 2px ink ring; errors are `--danger`.
- **Type:** Archivo (variable, self-hosted, OFL — `src/lib/assets/archivo-latin-var.woff2`) for everything: normal width for UI; `--font-display` at `--display-stretch` (62%), weight 900, uppercase for the wordmark, titles, big numbers, key name, section/drill/tune names. Chords always go through `ChordSymbol` (same condensed face, no capitals; ♭/♯ are DRAWN as inline SVG because Archivo has no such glyphs and the system fallback looked wrong; slot faces size to their slot with container units, never ellipsized). **Never uppercase a musical name** — `text-transform: uppercase` turns "ii–V–I" into "II–V–I" and "Bb" into "BB"; route roots through `ChordSymbol` (the key name does) and leave preset/example/starter names in their own case. **Petaluma Script survives only in the notation staff and its export** (`notation/font.ts` FontFace; `--font-hand` is kept for that). `.label` (11px, 800, uppercase, tracked) is for field names and group titles; sentence text is `.hint`. No eyebrow labels above headings.
- **Dark = the same tokens redefined** by the `night` mixin (ids stay `day`/`night`), applied for `:root[data-theme='night']` and under `prefers-color-scheme: dark` unless `data-theme='day'`. Dark is an OLD black sleeve, never digital black: warm charcoal `#1c1915` board, aged-paper ink `#ede4d3`, chord inks printed slightly muted, and a print grain (`--grain`, a fixed overlay-blended `body::after`, dark only). A sounding chord is still a solid block with dark `--on-pigment` text — never tint a dark surface with a translucent colour. Anything drawn outside CSS must follow `view.night`: every VexFlow SVG root is inked via `:global(svg) { fill/stroke: var(--ink) }` (StaffSheet, ScaleStaff, DrillStaff — the drill staff once drew black staves on plum, 1.29:1); DrillStaff/ScaleStaff put `view.night` in their render signature because note colours are resolved at draw time. The piano keyboard uses `--key-light/--key-dark` so it stays a piano at night; the record's vinyl is black on either board.
- **The music art reads the music, never a clock of its own.** `engine.clock()` (read at `Tone.immediate()`, so it matches what you hear) → `MusicClock`. Silence = stillness: the grooves' stylus (LoopRings) runs a rAF only while this song plays; the field and the record are event-driven. Reduced motion → the stylus steps per bar. There is no scenery (the golden-hour sky, sun, meadow and sunflower were retired in the Sleeve redesign); a new art piece must follow the same rule or it's a screensaver.

## Gotchas

- **VexFlow noteheads/clef are FONT GLYPHS** → DOM `getBBox` returns the em-box. Use VexFlow's own `note.getBoundingBox()` / `stave.getYForLine` for vertical layout. VexFlow is **lazy-imported** (`await import('vexflow')`) in StaffSheet/ScaleStaff — keep it out of any storage/server-loadable module. `await ensureJazzFont()` before draw so metrics are real.
- **VexFlow ignores inherited CSS custom props** — resolve `--c-*` to hex via `getComputedStyle` before `setStyle` (StaffSheet/ScaleStaff/DrillStaff). ScaleFretboard is plain Svelte SVG, so it uses `var(--c-*)` directly.
- **`beatsToVexDuration` floors at `'8'`** — anything shorter notates as an eighth, and `beats: 1/3` (triplets) has no representation at all. Drill patterns are therefore eighth notes or longer. Adding a `'16'` branch touches a tested module; triplets need a real tuplet model.
- **`flattenSlots(loopBars(p))` re-bases the index to the LOOP**, so it is NOT the index the engine highlights. Anything mapping loop-relative slots back to the UI must add the loop's start offset — exactly the bug the "flattenSlots is the single source" rule exists to prevent.
- **The Practice runner renders only the CURRENT key**, not the whole run. Drawing all repetitions put four keys on one 1195px-tall staff; now it is ~350px. `DrillStaff` re-flows on WIDTH change only (the StaffSheet rule).
- **`DrillStaff`'s render effect depends on `signature` and NOTHING else — the render runs inside `untrack()`.** Once VexFlow has loaded, `render()` calls `draw()` synchronously, so without `untrack` every `$state` it touches becomes a dependency: `notes` by identity (re-rendering musically identical notation on every upstream recompute) and the chord-label array. `draw()` also used to `.push()` into that `$state` array — reading what it wrote — so the effect re-scheduled itself on every render: **a loop that froze the page on every drill with chord labels, i.e. every drill over your own changes.** Build derived output in a local, assign once; anything `draw()` needs belongs in `signature`.
- **Keyed `{#each}` over layout output must key on POSITION** (`x,y`), not content. Chord labels were keyed `x + text`; on a long tune the form repeats, so the same chord lands in the same column on different rows, Svelte threw `each_key_duplicate` and dropped every label. It only surfaced once long tunes stopped being skipped.
- **The measure pass probes EVERY note, deliberately.** Probing only the extremes was built and A/B-measured: ~3ms saved on a 65-note staff (47 → 44ms median) because the final pass and the label DOM dominate — and to be correct at all it needed ranking by DRAWN position, not MIDI (`E#` sits below `F`, `Cb` above `B`; stems flip at the middle line). Not worth it; don't re-attempt without a profile showing the probe dominates.
- **Drill notation is deliberately plain black, with no moving playhead.** Both were tried and removed: role-coloured noteheads stopped it reading like sheet music, and tracking a per-note overlay meant animating `left`/`top`, which forces layout on every note and was visibly rough at drilling tempos. `practice.cue` still drives which KEY is on screen (once per repetition, not per note); progress is reported as text.
- **VexFlow's formatter OVERFLOWS the stave rather than compressing** below its own minimum spacing (~66px per eighth note with accidentals). `DrillStaff` fits the notes-per-row to the width against `MIN_NOTE_W`, and below `NARROW_W` scales the whole context by `NARROW_SCALE` — layout maths stays in logical units, only the canvas size and the HTML chord labels multiply by it. Without that, 16 notes on a 345px phone staff ran a third of every row off the screen.
- **VexFlow CANVAS backend (export/notation.ts):** glyphs (clef/noteheads/rests) draw with the AMBIENT `fillStyle` — after painting white paper, reset fill/stroke to black or every glyph is white-on-white (staff lines still show: they're stroked). A `Stave(x, y, w)`'s top LINE sits ~40px BELOW `y` — probe `getYForLine(0/4)` on a throwaway Stave, never assume. Use `CanvasContext.resize(w, h, ratio)` for supersampling, not a hand-rolled `ctx.scale`. Verify exports VISUALLY (save the PNG and look), not by ink-pixel counts alone.
- **StaffSheet ResizeObserver re-flows on WIDTH change only** (>1px, `lastWidth`-guarded); reacting to height loops forever (auto-sizing changes height). Two-pass layout (measure, then pack); chord names are our own SVG `<text>`, not VexFlow annotations; the active-highlight is a separate no-re-render `$effect`. Chart mode (`showNotes=false`) builds `b/4` placeholders and hides them via CSS.
- **tonal `midiToNoteName` defaults to FLATS.** Never respell staff pitches from MIDI. `voicedToVexKey` keeps F#/Bb; `midiToVexKey` is the flat-only fallback.
- **Enharmonic roots:** SCALE_ROOTS / PRESET_ROOTS are flat-spelled; selects add a synthetic `custom` `<option>` so sharp roots (and an imported 7/8 time-sig) never render blank. `inspire.ts` ROOTS is the one deliberate F#-using exception.
- **The preview/MCP tab suspends rAF** (and often stops rendering frames at all: screenshots time out or come back stale, transitions freeze, IntersectionObserver fires late). You cannot watch the grooves' stylus or any Draw-driven highlight there — verify via the DOM (groove count, `.dock--shown`, the computed `--field` on `<html>`), and the pure maths in `art/art.test.ts`. Grooves DO count in the pane: they come from `engine.onLoop`, which the transport fires without rAF. Headless Chrome screenshots (`chrome --headless=new --screenshot`) are a good full-page check, but it enforces a ~500px minimum layout width — check phone widths in the pane with `resize_window` instead.
- **`Tone.getDraw()` callbacks queue ~lookAhead ahead and outlive `transport.cancel()`** — the `setActiveSlot` draw is guarded by `this._state==='playing'` or a slot stays lit after stop.
- **smplr defaults to a REMOTE sample CDN** — true offline relies on the PWA runtime cache `'vamp-samples'` (CacheFirst); samples are NOT self-hosted. A failed load is evicted from the cache by identity (instruments.ts / getDrumMachine) — caching a rejected load would break that instrument for the whole session.
- **iOS drops the context to suspended/interrupted on background;** context.ts retries resume on visibility/statechange but may no-op — only the next real gesture recovers it. Don't trust `isRunning()` after backgrounding.
- **`tone` imports FINE in node** (context.ts is lazy — only `getRawContext()`/`Tone.start()` touch the AudioContext), so the db→instruments→context→tone chain loads in tests. Stores are untested because they drive a real Transport clock, not because Tone fails to import.
- **Web MIDI (input.ts) is Chromium-only**, needs a permission grant, and `navigator.requestMIDIAccess` may be absent (check `.supported`). Chord detection fires only on FULL release (`held.size→0`) using the peak set; a device unplugged mid-hold sends no note-offs, so `onstatechange` clears held+peak on any disconnect.
- **`+layout.svelte` SW registration is dynamic-imported + try/catch** because `virtual:pwa-register` is absent in dev (failure is silent). `<svelte:head><title>` in `+page.svelte` sets `document.title` client-side; because `ssr=false` the `app.html` title is only the no-JS fallback — don't duplicate it.
- **`share.encodeProgression` strips id + timestamps;** decode re-mints them via `migrateProgression` → opening a shared link creates a FRESH record that won't overwrite a saved one (nor the draft — see the adopt rule).
- **`library` callers are fire-and-forget** — IndexedDB rejections set `library.error` (except `import()`, which throws on bad JSON). `db.getDb()` clears its cached promise on open failure so the next call retries.
- **recorder Takes are in-memory object URLs** — `remove()`/`clear()` must `revokeObjectURL` or they leak; takes vanish on reload by design.

## Testing

- Vitest 4, `environment: 'node'` (NOT jsdom; the `$lib` alias is mirrored, the SvelteKit plugin is deliberately omitted). No setupFiles/globals — every test imports `{ describe, it, expect }` from `'vitest'`. Colocated `foo.ts` + `foo.test.ts`. ~32 files / ~400 tests, runs in ~3s.
- **A module that imports `$app/*` cannot be tested here** — that is why `TEMPO_MIN/MAX` live in `model/factory` and `TRANSPOSE_OPTIONS` in `audio/transpose`, each re-exported by its store. Put anything worth testing below the store layer.
- **TESTED = the pure, deterministic layer:** music theory (audio/chord, transpose, voicing; model/key, scales, presets, examples, inspire; midi/input), timing (model/time, audio/tapTempo, drills), arrangement (comp.buildCompEvents, mix), plans (audio/plan.countInFor, schedule.progressionPlan — incl. the voice-preload table, the one place a typo makes *wrong audio* not a crash), practice (spelling, range, sequence, resolve, plan), IO (export/midi bytes, storage/import + db.migrateProgression, storage/draft incl. corrupt / hostile / throwing storage), art MATH (art/music, rings, seedhead — `art/art.test.ts`), chord setting (model/symbol), and the stand cue (model/cue).
- **Practice's load-bearing tests:** the exhaustive root×scale-type sweep for double accidentals (with Gb major's `Cb` and F# major's `E#` pinned); `(fitted - raw) % 12 === 0` for every range shift; the B♭-trumpet round trip (every note exactly +2 vs the same drill at concert — catches an offset applied twice or backwards); a `voicedToVexKey` round trip on every generated note, which proves `name`↔`midi` survived range fitting better than any grep could; the ii-V-I guide-tone lines asserted by ROLE sequence, not raw MIDI; and `migrateDrill` fed hostile input, asserting the resolver still yields a finite, ordered, positive-duration schedule.
- **Assert music by pitch-class set (chroma mod 12)**, not raw MIDI arrays or symbol equality — reuse `chromaSet`/`expectedChroma` (voicing.test.ts). Re-parse detected/transposed symbols with tonal `Chord.get` and assert tonic+quality. **Randomness is injected** (`rand: () => number = Math.random`); tests pass a seeded LCG.
- When you add a `migrateProgression` coercion or a new example/preset, extend `import.test.ts` / `examples.test.ts` / `presets.test.ts` (they assert every generated chord is valid across roots and that legacy/hostile values are made safe).
- **UNTESTED (can't be, in node) — verify by hand in a browser:** everything stateful/side-effecting — engine, drone, scalePlayer, context, recorder, export/audio (need a live AudioContext/Transport/MediaRecorder/OfflineAudioContext), instruments sample loading (network), all `*.svelte` components (need DOM + font-glyph metrics), the runes stores (non-deterministic glue), and the canvas rAF loop.
- **Editing a `stores/*.svelte.ts` file with the dev page open leaves TWO store instances alive** (Vite HMR re-evaluates the module; the old component tree keeps the old singleton). Symptoms: a setter appears not to stick, `localStorage` disagrees with the store, or a component seeds from stale state. Always hard-navigate before believing a store bug in dev.
- **A console `await import('/src/lib/stores/x.svelte.ts')` can get a DIFFERENT instance than the page, even after a hard reload** — once a store has been edited, Vite serves the page's copy with a `?t=` timestamp and your import resolves to a separate module record. Setters then change a store nothing is rendering, and the page looks "stuck". **Drive the real UI (set the `<select>` and dispatch `change`) to test store behaviour.** Pure modules are stateless, so importing them to time or reproduce logic is fine.
- **Never compare absolute notehead y across renders.** A register change alters how far notes reach above the staff, so the whole staff MOVES down the page between renders; "higher on screen" across renders means nothing. A `.vf-stavenote` box also includes its stem, and an up-stemmed G4 reaches as high as a G5 notehead. Decode pitch against that render's own staff lines instead (top line = F5, one half-space = one diatonic step).
- **The MCP/preview pane suspends rAF entirely** (0 ticks, even with `visibilityState: 'visible'`), and `Tone.getDraw()` is rAF-flushed — so NEITHER highlight (chord slot or drill cue) can be watched moving there. Verify the rest of the chain instead: wrap the loaded instrument's `start` to count notes reaching it, read `engine.playGen` to prove restarts/live changes, and inspect the Draw queue length to prove callbacks were scheduled. The highlights themselves still want one look in a real browser.

## Org policy

- Distinguish PoC vs production; flag shortcuts/missing concerns explicitly. This repo is a delivered personal MVP.
- pnpm with `--ignore-scripts` + `minimumReleaseAge`; minimise deps (prefer built-ins — the MIDI writer and share codec are already dependency-free).
- Never hardcode secrets; no PII / client-proprietary data.
- **ALWAYS ask before `git push` / deploy** (a push to `main` triggers the Pages deploy).
